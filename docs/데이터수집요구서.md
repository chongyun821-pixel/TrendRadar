# 무기조달사업예상 데이터 수집 요구서

한화그룹 방산 부문의 수출 전략을 돕기 위한 문서예요. 무기 소요를 예측하는 데 필요한 데이터를 어디서 모으고, 어떻게 저장하고, 어떤 비중으로 판단할지 정해요.
기존 앱 구조(Supabase `countries`, `systems`, `sources`, `records`, `forecasts` 테이블, Firecrawl 조사, `templates/research-v1.md`)를 그대로 확장하는 것을 전제로 해요.

## 1. 대상 체계

| 앱 모드 | 그룹사 체계(예) | 주요 경쟁 체계(예) |
|---|---|---|
| 호위함 | 한화오션 호위함 | FREMM, FDI, MEKO A-200, Type 31 |
| 재래식 잠수함 | KSS-III(장보고-III) | Type 214/212CD, Scorpène, A26 |
| 자주포 | K9 | PzH 2000, CAESAR, Archer, M109A7 |
| 다연장로켓 | 천무 | HIMARS/M270, PULS |
| 대공미사일 | 천궁-II(한화 참여) | NASAMS, IRIS-T SLM, SAMP/T, Patriot |
| IFV | 레드백 | Lynx, CV90, ASCOD |

- 기존 `장갑차` 모드는 `IFV`로 바꿔요.
- 체계마다 대응 관계(대체, 경쟁, 상위 체계)를 `system_links`에 저장해요.

## 2. 소스와 추출 항목

| 판단 단계 | 소스 | 추출할 데이터 |
|---|---|---|
| 고객 등급(수출 가능성) | SIPRI 무기 금수 DB, UN 안보리 제재 목록, EU 무기 금수 목록, 미국 ITAR 126.1조 금지국, 전략물자관리원 수출통제 정보, SIPRI 이전 DB의 한국산 수출 이력 | 금수, 제재 여부, 미국산 부품 재수출 제한, 한국과의 방산 협정, 기존 수출, 분쟁 당사국 여부 |
| 도입 의사 표명 | 각국 국방부, 조달청 발표, EU TED 입찰, Defense News, Breaking Defense, Naval News, Army Recognition, X 뉴스 | 국가, 체계, 요구 수량, 예산, 예상 시기, 단계(검토, 입찰, 선정, 계약) |
| 1. 노후 교체 | SIPRI Arms Transfers DB, UN 재래식 무기 등록부(UNROCA), 위키백과 각국 군 장비 목록(보조) | 보유 모델, 수량, 도입 연도, 개량 이력 → 퇴역 예상 연도 |
| 1, 2. 재정 여력 | SIPRI Military Expenditure DB, NATO 국방비 보고서, IMF WEO | 연도별 국방비(USD), GDP 대비 비율, 전년 대비 증감률 |
| 2. 주변국 균형 | 위 보유, 이전 DB와 뉴스, GDELT(뉴스 이벤트, 논조, 무료), UCDP(분쟁 데이터, 무료), Natural Earth 국경 데이터(앱에 이미 있음) | 인접국 보유 현황, 신규 구매 소식, 인접국 국방비 증감, 국가 쌍별 분쟁, 적대 이벤트 |
| 3. 소모 보충 | Oryx(사진으로 확인된 손실), Kiel Ukraine Support Tracker, UCDP, CSIS Missile Threat | 전쟁별, 국가별 체계 손실과 소모량, 지원국→수혜국 공여 내역 |
| 3. 공급 능력 | 경쟁사 IR, 연차보고서, 생산 증설 보도 | 연간 생산량, 수주잔고, 납기 |
| 최종. 경쟁사 | SIPRI Arms Industry Top 100, 경쟁사 IR, 수주 보도 | 최근 5년 수주 실적(국가, 체계, 금액), 기술 사양 비교 |
| 최종. 독자 개발 | 각국 국방 획득 계획, 방산 기업 목록, 기술 이전, 현지 생산 사례 | 동급 체계 자체 개발 여부, 단계, 현지 생산 요구 |

- 모든 수치에는 출처 URL, 발행일, 수집일, 신뢰도를 함께 저장해요. 신뢰도는 공식 발표, DB 1.0, 전문 매체 0.7, 일반 뉴스, X 0.4로 매겨요.
- 유료 DB(IISS, Janes)는 쓰지 않아요. 보유 현황의 빈칸은 SIPRI 이전 기록을 누적해 추정하고, 위키백과, 뉴스는 신뢰도를 낮춰 보조로만 써요.
- 정기 DB(SIPRI, World Bank, UCDP)는 연 1회 일괄 적재해요. 뉴스, 입찰 정보는 Firecrawl 조사 흐름으로 수시 갱신해요.
- 기준 연도는 운영 데이터 `meta.baseYear` 하나만 써요(현재 2026). 화면, 보고서, 예측, 점수, 조사 양식과 등급, 긴장도 산출이 모두 이 값을 쓰고, 컴퓨터 시계의 올해로 바꾸지 않아요. 수집 스크립트의 `--year`는 내려받을 자료 범위에만 써요.
- 이 문서의 '최근 3년'은 2023~2026(기준 연도 포함 4개년), 즉 기준 연도−3년부터 기준 연도까지예요. 코드에서는 `shared/base-year.ts`의 `recentFrom`, `isRecent`로 계산해요.

## 3. DB 스키마 추가안 (PostgreSQL)

기존 테이블은 그대로 두고 아래 테이블을 추가해요. 공통 컬럼 `source_id`, `confidence`, `collected_at`은 표기를 생략했어요.

```sql
-- 체계 대응 관계 (그룹사 체계 ↔ 경쟁, 대체 체계)
CREATE TABLE system_links (system TEXT REFERENCES systems(id), model TEXT, maker TEXT,
  is_group BOOLEAN, relation TEXT, PRIMARY KEY(system, model));

-- 국가 수출 등급(수출 가능/조건부 수출 가능/수출 불가)과 등급 근거
ALTER TABLE countries ADD COLUMN tier SMALLINT, ADD COLUMN tier_reasons JSONB, ADD COLUMN tier_checked_at DATE;

-- 인접, 경쟁국 관계와 자동 산출 긴장도 (2번 케이스용)
CREATE TABLE neighbors (country TEXT, neighbor TEXT, kind TEXT,  -- land | sea | rival
  tension NUMERIC, components JSONB, computed_at DATE, PRIMARY KEY(country, neighbor));

-- 보유 체계와 도입 이력 (1번 케이스용)
CREATE TABLE inventory (id TEXT PRIMARY KEY, country TEXT, system TEXT, model TEXT,
  quantity INT, delivered_year INT, service_life INT, retire_year INT);

-- 국방비 (1, 2번 케이스용)
CREATE TABLE budgets (country TEXT, year INT, usd_m NUMERIC, gdp_pct NUMERIC, yoy_pct NUMERIC,
  PRIMARY KEY(country, year));

-- 도입 의사, 입찰, 계약 신호 (초기 결정, 2번 케이스, 경쟁사 수주)
CREATE TABLE signals (id TEXT PRIMARY KEY, country TEXT, system TEXT, model TEXT, maker TEXT,
  stage TEXT, quantity INT, value_usd_m NUMERIC, expected_year INT, published_at DATE, url TEXT);

-- 전쟁 소모 (3번 케이스용)
CREATE TABLE consumption (id TEXT PRIMARY KEY, conflict TEXT, user_country TEXT, target_country TEXT,
  system TEXT, model TEXT, quantity INT, period TEXT);

-- 공급사 생산 능력 (3번 케이스용)
CREATE TABLE supplier_capacity (maker TEXT, model TEXT, year INT, annual_output INT, backlog INT,
  PRIMARY KEY(maker, model, year));

-- 독자 개발 능력 (최종 필터)
CREATE TABLE domestic_capability (country TEXT, system TEXT, status TEXT, program TEXT,
  PRIMARY KEY(country, system));

-- 판단 비중 (코드 수정 없이 조정 가능)
CREATE TABLE weights (factor TEXT PRIMARY KEY, weight NUMERIC, note TEXT);
```

`forecasts.data`에는 아래 항목별 점수와 근거 ID 목록을 함께 저장해서, 리포트에서 바로 인용할 수 있게 해요.

## 4. 고객 등급(수출 가능/조건부 수출 가능/수출 불가)

고객 등급은 경제 수준이 아니라 수출 가능성을 기준으로 나눠요. 아래 규칙을 순서대로 적용해 자동으로 판정하고, 판정 근거는 `tier_reasons`에 남겨요.

| 등급 | 기준 | 앱 처리 |
|---|---|---|
| 수출 가능 | 제재, 금수 없음, 한국과 방산 협정 또는 한국산 무기 수입 이력 있음, 미국산 부품 재수출 문제 없음 | 정상 점수 |
| 조건부 수출 가능 | 제재는 없지만 협정, 수출 이력이 없거나, 분쟁 당사국이거나, 미국산 부품 때문에 재수출 승인이 필요함 | 점수 × 0.7, 리포트에 승인 필요 사항 표시 |
| 수출 불가 | UN, EU, 미국 제재나 금수 대상, 또는 북한, 러시아 등 한국 수출통제 대상국 | 점수 0, 지도에 회색 표시 |

- 체계별로 미국산 부품 사용 여부가 다르므로, 등급은 국가 × 체계 단위로 한 번 더 확인해요.

## 5. 인접국 긴장도 자동 산출

1. 인접국 쌍은 앱의 Natural Earth 국경 데이터에서 육상 국경을 뽑아요. 해상 인접은 일정 거리 안의 국가로 정하고, 최근 5년 GDELT 적대 이벤트 상위 국가를 경쟁국으로 더해요.
2. 긴장도(0~100)는 매월 아래 항목으로 다시 계산해요.

| 구성 요소 | 비중 | 소스 |
|---|---|---|
| 무력 충돌, 사상자 | 35 | UCDP(최근 3년: 2023~2026(기준 연도 포함 4개년)) |
| 적대 이벤트 빈도, 논조 | 25 | GDELT(최근 12개월, 위협, 제재, 군사 행동 이벤트 수와 Goldstein 지수) |
| 군비 경쟁 | 20 | 두 국가 국방비 증가율, 상대국 신규 구매 건수(`signals`) |
| 영토, 해양 분쟁 | 20 | 분쟁 지역 목록(위키백과 영토 분쟁 목록을 기준으로 정적 관리) |

- 두 국가가 같은 동맹(NATO 등)이면 30% 감산해요.
- 구성 요소별 값은 `components`에 저장해서, 리포트에서 왜 이 점수가 나왔는지 보여줘요.
- 신뢰도는 근거가 된 자료(충돌, 이벤트, 구매 신호, 국방비)의 최소 신뢰도예요. 영토 분쟁 정적 목록은 0.4로 봐요.
- 네 요소 모두 근거가 없는 쌍은 0점 대신 추정값을 써요. 같은 산출에서 근거가 있는 쌍의 긴장도 중앙값(두 국가 중 한쪽이 들어간 쌍 우선, 없으면 전체 쌍)을 쓰고, 근거 있는 쌍이 하나도 없으면 기본값 10을 써요. 같은 동맹이면 30% 감산하고, 신뢰도는 0.2로 두며, `components.estimated`에 규칙을 남겨 리포트에 '추정'으로 표시해요.

## 6. 판단 비중

### 통과 조건

먼저 아래 두 조건을 확인해요. 하국가도 걸리면 점수를 0으로 처리하고, 지도에는 회색으로 표시해요.

- 고객 등급이 수출 불가인 국가는 제외해요.
- 동급 체계를 이미 독자 개발해 양산 중인 국가는 제외해요. 개발 단계라면 감점만 해요.

### 점수 (100점)

| 항목 | 비중 | 산식 요약 |
|---|---|---|
| 도입 의사 표명 | 20 | 단계별 점수(검토 5, 입찰 15, 선정 대기 20) |
| 노후화 | 20 | 퇴역 예상 연도까지 남은 기간, 교체 대상 수량 |
| 재정 여력 | 15 | 국방비 3년 평균 증가율, GDP 대비 비율 |
| 주변국 압력 | 15 | 인접국 신규 구매 건수, 인접국 국방비 증가율 × 자동 산출 긴장도 |
| 소모 보충 | 10 | 소모, 공여량 대비 재고, 기존 공급사의 수주잔고와 납기 |
| 경쟁 우위 | 15 | 경쟁사 수주, 납기, 가격, 현지 생산 조건과 비교 |
| 접근성 | 5 | 한국과의 협력 이력, 기존 한국산 운용 여부 |

- 최종 점수는 항목 점수 × 출처 신뢰도 × 등급 계수(수출 가능 1.0, 조건부 수출 가능 0.7)로 계산해요.
- 지도 히트맵은 기존 방식대로 그려요. 색은 임박도를 나타내고, 도입 의사 시기와 퇴역 연도 중 가까운 쪽을 써요. 높이는 규모를 나타내고, 예산이나 수량으로 정해요.
- 비중은 `weights` 테이블에서 바로 조정할 수 있어요.
- 도입 의사는 최근 3년(2023~2026, 기준 연도 포함 4개년)에 나온 신호와, 그보다 오래됐어도 예상 시기가 기준 연도 이후인 신호를 봐요. 재정 여력의 3년 평균 증가율은 같은 4개년 국방비로 계산한 2024~2026년 증가율이에요. 주변국 신규 구매와 분쟁 당사국 판정도 같은 범위를 써요.
- 노후화에서 보유 행에 인도 연도(`delivered_year`)와 퇴역 연도가 모두 없으면 인도 연도를 추정해요. 같은 모델의 기존 기록 배치 도입 연도 → 같은 모델의 계약, 인도 신호 중 가장 이른 연도 → 기준 연도 − 설계 수명의 절반(수명 중간에 있는 전력으로 가정) 순서예요. 추정 행의 신뢰도는 원래 신뢰도에 근거 있는 추정이면 0.7, 기본값이면 0.4를 곱하고, 근거 표에 '추정'으로 표시해요.
- 설계 수명은 `systems.lifeSrc`에 출처가 있을 때만 확인값으로 보고, 출처가 없으면 '추정'으로 표시해요.

## 7. 구현 순서

1. 스키마를 마이그레이션하고 모드를 정리해요(장갑차를 IFV로 변경).
2. SIPRI(무기 이전, 국방비, 금수), World Bank, UCDP, Oryx를 일괄 적재하는 스크립트를 만들고, 고객 등급 판정 규칙을 구현해요.
3. GDELT 월간 집계와 긴장도 계산 작업을 만들어요.
4. `templates/research-v1.md`에 `signals` 추출 형식을 추가하고, Firecrawl 조사 결과를 정규화해요.
5. `shared/forecast.ts`에 점수 산식을 적용하고, MCP 도구 `get_score_breakdown`을 추가해요.
6. 리포트 템플릿에 케이스별 근거 표를 넣어요.

## 8. 확정 사항

- 유료 DB는 구독하지 않고, 무료 공개 소스만 써요.
- 고객 등급은 수출 가능성을 기준으로 자동 판정해요(4장).
- 인접국 긴장도는 매월 자동으로 산출해요(5장).
