# 지구 표면과 국가 데이터 레이어

## 바탕 자료

`public/earth/`의 JPEG 3개는 NASA Earth Observatory가 제공하는 Blue Marble: Next Generation 자료다. 앱은 로컬 파일을 제공하며 실행 중 외부 지도 서비스에 접속하지 않는다.

- `surface.jpg`: 2004년 7월의 표면 색과 음영 지형. [원본 안내](https://science.nasa.gov/earth/earth-observatory/blue-marble-next-generation/base-topography/).
- `height.jpg`: 0~6,400m 범위의 육지 고도. [고도와 수심 자료 안내](https://science.nasa.gov/earth/earth-observatory/blue-marble-next-generation/topography-bathymetry-maps/).
- `depth.jpg`: -8,000~0m 범위의 수심. 같은 안내의 GEBCO 자료이며 Jesse Allen, NASA Earth Observatory와 British Oceanographic Data Centre를 출처로 표시한다.

원본 URL, NASA 이미지 서버의 축소본 URL, 받은 날짜, 파일 크기와 SHA-256은 `public/earth/sources.json`에 보존한다. 색상은 4096×2048, 고도와 수심은 각각 2048×1024로 받아 GPU 메모리 사용을 줄였다. 이 지도는 현재 위성 영상이나 정밀 측량용 모델이 아니다.

## 렌더링

`src/earth-surface.ts`가 표면, 고도, 수심 텍스처와 공통 셰이더를 제공한다. 고도는 실제 표면 정점을 이동시키며 최대 변위는 반지름 100에서 0.16이다. 지형 음영은 고도와 수심의 경사로 세부 굴곡을 표현하고, 바다는 수심에 따라 짙은 남색에서 청록색으로 변한다.

국가 채움은 같은 경위도의 바탕 지형과 데이터 색을 기본 85% 비율로 합성한다(투명도 15%). 색칠한 영역의 바탕은 채도와 밝기를 낮춰 사막과 식생의 색이 무기별 색과 교체 시기별 농도 차이를 흐리지 않게 하고, 지형 굴곡은 은은하게 남긴다. 자료 없는 국가는 자연색을 유지하며 약한 중성색만 덮고, 빗금 사이로도 지형을 남긴다. 빗금의 최대 불투명도는 94%로 제한해 과도한 색상 합성을 막는다. 국가별 원래 RGB, 교체 시기별 강도, 점수와 빗금 판정은 그대로 유지한다. 불투명한 최종 표면에서 합성하므로 투명 삼각형의 정렬이나 지구 뒷면 비침 문제가 생기지 않는다.

바탕, 국가, 국경은 같은 고도와 구면에서 평면으로의 좌표 변환을 사용한다. 고도 변위를 레이어 간격보다 작게 제한하고 막대와 원의 시작점을 표면 위에 두어 지형에 가려지는 것을 막는다. 경위도에 고정한 텍스처는 회전, 확대, 2D 전환, 날짜변경선 반복에서도 유지된다. 이미지 로드에 실패하면 외부 요청으로 대체하지 않고 단순 바탕을 사용한다.

2D 금액 원은 원래 무기 색조를 유지한 채 밝은 톤으로 표시하고, 같은 계열의 짙은 테두리를 원 안쪽에 그린다. 원은 불투명하게 표시해 국가 배경색과 구분하며, 테두리가 원 밖으로 확장되지 않아 금액에 따른 지름과 일정한 두께는 유지한다. 3D 막대는 원래 색을 사용하고, 강조에서 제외해 어둡게 표시한 원은 밝게 올리지 않는다. 3D와 2D 사이에서 색과 테두리도 부드럽게 전환한다.

체계별 원의 톤 조정은 `src/map-style.ts`의 `CIRCLE_TONE`에서 정의한다. 자주포는 기존 색조를 유지하면서 채도를 높이고 명도를 조절한 주황색(`#fda262`)을 사용한다. 다른 체계는 기본 밝은 톤을 유지하며, 원의 톤 설정은 국가 채움이나 3D 막대의 원색에 적용하지 않는다.

## 확인

`npm run build` 후 `npm run map:check`로 별도 SQLite 서버와 가상 자료에서 지구본과 2D 지도, 데스크톱과 모바일을 확인한다. 바탕만 표시한 픽셀과 색상을 합성한 픽셀을 비교해 지형 굴곡이 남는지 검사하고, 불투명도 55%와 비교해 지형의 간섭과 원래 국가 색과의 차이가 줄었는지 확인한다. 2D 원은 바탕과의 픽셀 명도 차이와 원래 무기 색조 유지도 검사한다. 빗금 고정, 반복 지도 선택, 원의 일정한 두께와 극지 이동 제한도 확인한다. 운영 DB와 모델은 사용하지 않는다.
