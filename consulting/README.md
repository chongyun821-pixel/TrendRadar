# H5S Studio

대화로 문제를 정리하다가 필요한 시점에 보고서 편집기로 이어지는 로컬 웹앱입니다. 기존 `procurement-radar`의 코드·설정·파일·DB는 변경하지 않습니다.

## 실행

Node.js 24 이상과 로그인된 Codex CLI가 필요합니다.

```powershell
npm install
codex login
npm run build
npm start
```

브라우저에서 **http://127.0.0.1:4318** 을 열고 채팅을 시작합니다. 제목이나 과제 등록 폼은 없습니다. 대화 중 보고서를 작성해 달라고 요청하면 지금까지의 내용으로 제목과 맥락을 정리하고 편집기를 엽니다. 다른 기기에 공개하지 않는 로컬 서버입니다.

`.secrets.example`을 참고하여 필요한 설정만 이 프로젝트의 `.secrets`에 지정합니다. 기본값은 옆 폴더 `../procurement-radar/.secrets`의 Supabase 연결정보를 서버에서 읽습니다. 기존 파일을 수정하거나 자격증명을 복제하지 않습니다. 별도의 `RADAR_DATABASE_URL`로 전용 읽기 전용 DB 역할을 설정할 수도 있습니다. 자격증명은 브라우저, 프롬프트, 로그에 전달하지 않습니다.

## 작성 흐름

1. 일반 채팅으로 질문하거나 자료를 첨부합니다. 이전 대화는 왼쪽 목록에서 이어갈 수 있습니다.
2. 실제 보고서 작성을 요청하면 등록 폼 없이 편집기가 열리고, 대화와 자료를 바탕으로 핵심 확인 질문과 추천 답변을 함께 준비합니다. 새 질문은 1~3개로 묶고 답변은 입력란의 기본값으로 저장합니다. 보고서 작성법을 묻거나 작성을 취소한 경우에는 일반 대화를 유지합니다.
3. 추천 답변을 그대로 사용하거나 필요한 부분만 수정한 뒤 ‘이 내용으로 초안 작성’을 누릅니다. 미확인 사실은 가정·제안·확인 필요로 구분합니다. 다음 페이지에서도 추천 답변을 자동 준비하며, 이전 보고서에 추천 답변이 없으면 기존 질문과 입력 내용을 보존하면서 추가합니다.
4. 브라우저의 문서를 직접 편집하거나 오른쪽 채팅으로 수정을 요청합니다. 변경 내용은 자동 저장됩니다. 텍스트 구조 편집과 서식 도구도 지원합니다.
5. 산출물을 확정하면 다음 산출물이 열립니다. 앞선 내용을 바꾸면 이후 확정은 다시 검토하도록 해제되며 본문은 남습니다.
6. 7페이지 전체를 미리 보고 HTML, PDF 또는 편집 가능한 Word 문서로 내려받습니다.

대화 목록의 휴지통 버튼으로 선택한 대화를 삭제할 수 있습니다. 확인창에서 삭제하면 이 앱에 저장한 대화·보고서·첨부자료·내보내기 파일과 실행·이벤트 기록을 지웁니다. 답변 생성·자료 처리 중에는 먼저 작업이 끝나거나 중지되어야 합니다. 연결한 Radar 원본이나 Codex CLI 자체의 별도 이력은 이 삭제 기능의 대상이 아닙니다.

첫 화면의 ‘월드은행 사례로 시작’은 첨부 H5S 교재 사진의 가상 국내 소매은행 적자 축소 사례를 새 대화에 넣습니다. 판독한 스토리와 원본 사진 사본을 첨부하고 일반 채팅으로 시작합니다. 보고서를 작성해 달라고 요청하면 추천 답변과 보고서 편집기로 이어집니다. 원본에 없는 손익·NIM·고객·채널 수치는 미확인으로 남깁니다.

문제정의서 편집·문서 보기는 교재 사진의 일곱 항목을 왼쪽 항목명·오른쪽 내용의 표로 표시합니다. 이슈트리는 기본 질문에서 세부 이슈로 이어지는 가로 도식으로 표시하고, 이슈 선택·내용 수정·가지 추가·삭제·되돌리기와 확대·전체 보기를 지원합니다. 기존 Markdown 초안과 출처를 보존하며 자동 저장·충돌 처리와 연동합니다. 복합 서식이 있는 이슈 목록은 구조 변경을 제한하고 텍스트 구조 편집을 제공합니다.

| 단계 | 보고서 페이지 |
| --- | --- |
| 1 문제 구조화 | 1 문제정의서, 2 이슈트리 |
| 2 가설 수립 | 3 초기가설 |
| 3 작업 계획 | 4 작업계획서 |
| 4 분석 | 5 Governing Thought Pyramid |
| 5 권고안 개발 | 6 스토리보드, 7 권고안 |

## Codex 연결

모델은 `gpt-6.1-sol`, 추론 강도는 `xhigh`로 고정합니다. 다른 모델로 자동 전환하지 않습니다. 기존 CLI 인증을 사용하므로 OpenAI API 키는 필요하지 않습니다.

일반 채팅은 [공식 비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode)의 `codex exec --ephemeral --json`을 매 요청 새 프로세스로 실행합니다. 설치된 CLI에서 `--execute`에 해당하는 명령은 `exec`입니다. 이전 대화와 누적 맥락을 다음 요청에 전달하고 원문은 현재 프로젝트의 워크스페이스에 보관하므로, 임시 CLI 실행이 종료되어도 앱의 대화는 남습니다. 읽기 전용 H5S MCP를 통해 기존 DB와 선택한 자료를 조회할 수 있습니다.

구조화된 응답의 `openReport` 동작으로 보고서 작성 의도를 전달받으면 같은 대화의 전체 원문·첨부자료·요약을 `chat-handoff.json`에 보관하고 보고서 편집기로 전환합니다. 일반 채팅의 임시 프로세스를 보고서 세션으로 재사용하지 않습니다. 보고서 편집기부터 아래 app-server 세션을 사용합니다. 내부 실행 방식과 단계·문서 수를 홍보하는 문구는 화면에 표시하지 않습니다.

[공식 Codex App Server 문서](https://learn.chatgpt.com/docs/app-server)의 stdio JSON-RPC 프로토콜을 사용합니다. 서버가 `codex app-server --listen stdio://` 프로세스를 실행하고, 브라우저 요청을 같은 thread의 `turn/start`로 전달합니다. 출력·도구 호출·초안 갱신은 SSE로 전달합니다. 보고서마다 하나의 thread ID를 보존하며, 연결이나 서버 재시작 뒤 `thread/resume`으로 복원합니다. 단계마다 별도 세션을 만들지 않습니다.

초안 갱신과 자료 조회는 app-server의 실험적 dynamic tools를 사용합니다. 검증한 CLI 버전은 **0.163.0**입니다. 다른 버전에서 프로토콜이 바뀌면 `npm run check:connections`와 `npm run check:live`로 확인합니다. 전역 Codex 설정을 변경하지 않으며, 이 앱의 CLI 프로세스에서 기존 procurement MCP 쓰기 연결을 비활성화합니다. 기본 셸은 읽기 전용 샌드박스를 사용하고 H5S 문서 변경은 버전 검사한 전용 도구로 처리합니다.

직접 편집과 AI 수정이 겹치면 사용자 본문을 덮어쓰지 않고 AI 제안을 별도 보관합니다. 다른 탭의 수정은 버전 충돌로 안내합니다. 저장하지 못한 편집은 브라우저 캐시에 복원용으로 보관합니다. 일반 채팅 중지는 해당 CLI 프로세스 트리만 종료하고, 보고서 작성 중지는 `turn/interrupt`로 전달합니다. 중지 후 늦게 도착한 보고서 전환이나 초안 변경은 반영하지 않습니다. 재시작 시 진행 중이던 요청은 중단 처리하고 자동 재실행하지 않습니다.

## DB와 대화 워크스페이스

- 기존 Supabase의 `trendradar` 스키마를 조회합니다. 모든 SQL 트랜잭션은 PostgreSQL의 `READ ONLY`로 실행하고 연결 기본값도 읽기 전용입니다.
- 기존 코드의 Repository를 초기화하지 않으므로 DDL·마이그레이션·운영 레코드 저장을 실행하지 않습니다. 기존 프로젝트에 파일을 쓰지 않습니다.
- 저장 경로를 기존 프로젝트 내부로 설정해도 시작 전에 거절합니다. 심볼릭 링크의 실제 경로도 확인하여 연결한 프로젝트에 H5S 파일이 생성되지 않도록 합니다.
- 조달 기록·출처·보고서 검색, 기존 대화 전체 메시지 및 자료 목록 조회를 지원합니다. 연결 실패를 샘플 데이터로 바꾸지 않습니다.
- 연결한 대화의 원본 파일은 원본 해시를 검증하고 읽습니다. 로컬 원본이 없으면 비공개 Supabase Storage에서 내려받아 **H5S 폴더에만 사본**을 보관합니다. 사용자와 Codex 모두 가져올 수 있습니다.
- H5S 대화·질문·답변·초안·버전·수정 제안·실행 및 이벤트는 `.local/h5s.sqlite`에 보관합니다. 각 대화의 `.local/workspaces/<대화ID>/`에 `conversation.json`, `conversation.md`, `report.json`, `report.md`, 첨부자료와 가져온 대화 원문을 보관합니다. `runs/<실행ID>/`에는 임시 CLI의 입력, JSONL 출력과 최종 응답이 남으며 보고서 전환 시 `chat-handoff.json`을 함께 보존합니다.
- 첨부 가능한 형식은 PDF, DOCX, TXT, MD, CSV, TSV, JSON, 이미지입니다. PDF와 Word는 텍스트를 추출하며 이미지는 Codex에 이미지 입력으로 전달합니다. 스캔 PDF에 추출 가능한 텍스트가 없으면 페이지 이미지 첨부를 안내합니다.

## 참고자료와 내보내기

[참고자료 판독본](docs/reference-extraction.md)은 원본 사진 8장을 직접 판독한 시각 OCR 결과입니다. 문제정의서의 7개 항목, S-C-Q와 이슈트리의 MECE·Relevant·Consistent 원칙을 적용합니다. 잘리거나 흐린 부분과 사진에 없는 팁은 구분했으며, 교육용 예시는 실제 분석 근거로 사용하지 않습니다.

HTML은 외부 리소스 없이 7개의 A4 페이지로 구성됩니다. 문제정의서는 7항목 양식, 이슈트리와 피라미드는 계층이 드러나는 레이아웃을 사용합니다. PDF 변환은 설치된 Chrome/Edge를 이용하고 실제 인쇄 영역의 넘침을 검사합니다. 내용이 한 페이지를 넘으면 422 응답으로 알려주며 원문을 자르지 않습니다. `CHROME_PATH`로 변환 실행 파일을 지정할 수 있습니다.

Word는 실제 OOXML 문단·목록·표와 7개 산출물 사이 페이지 나누기를 생성합니다. Word의 실제 페이지 수는 폰트와 편집 내용에 따라 달라질 수 있습니다. 이 환경에서는 구조 및 텍스트 추출 왕복 검증을 완료했으며 Word 자체 렌더링은 검증하지 못했습니다. PDF와 똑같은 인쇄 페이지 수가 필요하면 PDF를 사용합니다.

## 확인 명령

```powershell
npm run build
npm test
npm run check:connections
npm run check:api
# 가상 교육용 과제로 실제 Codex를 호출합니다. CLI 사용량이 발생합니다.
npm run check:live
npm run check:chat
```

실제 검증은 `.local/verification/`의 별도 저장소에서 수행하며 기존 운영 대화에 테스트 메시지를 삽입하지 않습니다. 연결 상태에는 계정·모델의 실제 확인 결과와 DB 조회 결과를 구분하여 표시합니다.

## 검증 범위

실제 임시 CLI 대화와 맥락 기억, 보고서 요청에 따른 자동 화면 전환 및 최초 질문 준비, 전체 대화 인계를 확인했습니다. 기존 보고서 세션 복원·초안 수정·Supabase 읽기 전용 검색·내보내기 검증도 유지합니다. 테스트에는 전환·취소·원문 보존과 첫 화면의 문구 검사가 포함됩니다. PDF는 7페이지 모두 렌더링하고 확인했습니다. 브라우저의 로컬 주소 접근 권한이 거부되어 화면 조작 및 모바일 화면은 자동 검증하지 못했습니다. Word 검수용 외부 변환 도구 다운로드·실행은 자동 승인 검토가 차단하여 Word 화면 렌더링은 미검증입니다.
